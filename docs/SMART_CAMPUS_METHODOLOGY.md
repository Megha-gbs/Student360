# Student360 — Smart Campus Analytics Methodology

## 1. Dataset Source & Provenance
- **Dataset Origin**: Higher Education Dropout and Academic Success Dataset (UCI Machine Learning Repository / Polytechnic Institute of Portalegre).
- **Physical Location**: `data/data.csv` (semicolon-delimited CSV, UTF-8-BOM encoded).
- **Record Count**: Exactly **4,424 total records** and **37 columns** (36 predictive features + 1 target variable `Target`).
- **Data Integrity**: 0 missing cells, 0 duplicate rows across all 4,424 records.
- **Target Distribution**:
  - `Graduate`: **2,209 students** (49.93%)
  - `Dropout`: **1,421 students** (32.12%)
  - `Enrolled`: **794 students** (17.95%)
- **Target Class Encoding in XGBoost**:
  - `0`: Dropout
  - `1`: Enrolled
  - `2`: Graduate
- **Deterministic Record Identifiers**:
  - Verified demo benchmarks (Rows 0, 1, 2, 4, 7, 8, 14, 25, 45, 100) are canonically mapped to `S1001` through `S1010` to preserve existing named demo users and test fixtures.
  - All other records are deterministically identified as `S1001`..`S5424` and also alias-resolvable via `UCI_0001`..`UCI_4424`.

## 3. Student Success Score Methodology
The Student Success Score is an explainable, multi-dimensional metric on a 0–100 scale evaluating holistic student engagement and momentum.

### Indicator Dimensions & Prototype Default Weights
| Component | Default Weight | Data Source / Basis | Missing Policy |
| :--- | :---: | :--- | :--- |
| **Academic Performance** | 35% (0.35) | Curricular units approved ratio & grade average | Derived from UCI academic fields |
| **Attendance** | 20% (0.20) | Overall & subject-wise attendance logs | Proxy / Ingestion interface |
| **LMS Engagement** | 15% (0.15) | Login frequency, assignment completion | Authorized LMS connector |
| **Student Engagement** | 15% (0.15) | Extracurricular, clubs, hackathons, certs | Student portfolio logs |
| **Placement Readiness** | 15% (0.15) | Aptitude, coding assessments, mock interviews | Placement portal logs |

### Dynamic Weight Renormalization Formula
When one or more data categories are unavailable:
$$\text{Weight Coverage} = \sum_{i \in \text{Available}} w_i$$

If $\text{Weight Coverage} \ge 0.30$ (minimum coverage threshold):
$$\tilde{w}_i = \frac{w_i}{\text{Weight Coverage}}$$
$$\text{Student Success Score} = \text{round}\left( \sum_{i \in \text{Available}} \tilde{w}_i \cdot S_i \right)$$

If $\text{Weight Coverage} < 0.30$, the system reports `status: "insufficient_data"` and does not output an ungrounded score.

### Standing Tiers
- **Exemplary**: 85–100
- **Good Standing**: 70–84
- **Developing**: 50–69
- **At Risk**: 0–49

## 4. Distinct Score Concepts
It is essential to distinguish the three complementary indices:
1. **XGBoost Dropout Risk (0–100%)**: Probabilistic classification generated by the supervised ML model evaluating probability of non-completion based on the 36 frozen UCI features.
2. **Student Success Score (0–100)**: Rules-based multi-factor composite index assessing academic standing, momentum, engagement, and attendance.
3. **Placement Readiness (0–100)**: Domain-specific readiness index evaluating aptitude, coding proficiency, technical skills, and mock interview performance.

## 5. Unified Student View: Data Categories & Ingestion Contracts
For categories beyond the static UCI dataset:
- **Academic**: Fully grounded in UCI Sem1 and Sem2 curricular units.
- **Attendance**: Validated via CSV import or API integration (`/attendance/*`).
- **LMS**: Connected via assignment submission and activity tracking (`/assignments/*`).
- **Engagement**: Maintained in verifiable student timeline entries (`/students/{id}/timeline`).
- **Placement**: Managed via aptitude and mock interview scoring (`/scoring/placement-readiness`).
- **Skills**: Profiled with verified credentials and badges.
- **Feedback & Surveys**: Role-restricted student satisfaction and faculty feedback.

*Data Provenance Rule: If data for a category is not present, it is explicitly shown as "Not available" or "Awaiting import" — never fabricated as zero or fictitious values.*

## 6. Explainability & SHAP Interpretation
- **Local SHAP Explanations**: Evaluated via TreeSHAP on the XGBoost model. Contributions from the 233 preprocessed dummy features are grouped back to the 36 parent UCI features to produce 3–5 human-readable risk drivers.
- **Global SHAP Cohort Importance**: Aggregates mean absolute SHAP values across representative cohort samples, identifying systemic drivers such as Sem 2 approved units, tuition fee payment status, and admission grade.
- **Scientific Framing**: SHAP reflects feature attribution and model sensitivity; it indicates correlational contribution within the trained decision trees, not causal proof.

---

## 7. Cohort Segmentation Rules
Segments are calculated using explicit deterministic criteria:
1. **High Academic Risk**: Curricular units 2nd sem (approved) $\le 2$.
2. **Financial Risk**: `Debtor == 1` OR `Tuition fees up to date == 0`.
3. **Retention Transition Risk**: Age at enrollment $> 25$.
4. **High Risk with Declining Trajectory**: Model Risk == High AND Sem 2 approved units $<$ Sem 1 approved units.
5. **Strong Academic Standing**: Total approved units (Sem 1 + Sem 2) $\ge 10$.
6. **Placement Preparation Needed**: Sem 2 approved units $\le 4$ or Placement Readiness $< 60$.

## 8. Role-Based Access Control (RBAC) & Privacy
- **Student Role**: Restricted strictly to own student ID. Cross-student profile access returns HTTP `403 Forbidden`.
- **Faculty Role**: Scoped to assigned students when an explicit assignment roster is defined.
- **Admin Role**: Full institutional scope across all 4,424 students, data imports, fee management, audit logs, and cohort insights.
